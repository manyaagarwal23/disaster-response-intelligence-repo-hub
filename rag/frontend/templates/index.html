Ushahidi Repository

Open-source crisis-mapping platform

A platform that collects information from the ground during crises and visualizes reports on maps to help responders identify where assistance may be needed.

What does this repository contain?

Data sources

Incoming reports from SMS, email, social media and web forms.

Posts and surveys

Structures collected reports and submitted information.

Geolocation and maps

Handles location data and crisis-map functionality.

REST API

Exposes platform functionality through API endpoints.

Roles and permissions

Controls user access and permissions.

Tests

Supporting tests for repository functionality.

How does Ushahidi work?

Information collection

Reports arrive from different channels

Report processing

Information is organized into posts and surveys

Geolocation

Location data is associated with reports

Crisis mapping

Reports are displayed for responders to explore

Why is this codebase significant?

Ushahidi is a large, interconnected PHP codebase. Understanding how its modules, classes, APIs and permissions work together can be challenging for developers who are new to the repository.

This makes it a useful real-world codebase for exploring software architecture, dependencies and the relationships between components.

About our project

Disaster Response Intelligence Repo Hub

Retrieval-Augmented Generation Code Intelligence AI Developer Assistant

What is this project?

Disaster Response Intelligence Repo Hub is an AI-powered chatbot designed to help developers understand large and unfamiliar codebases. It uses Retrieval-Augmented Generation (RAG) to search repository code, retrieve relevant information and generate context-based explanations with source references.

Instead of manually searching through thousands of lines of PHP code, developers can ask questions in plain English and receive understandable explanations about classes, methods, dependencies and workflows.

Ask in natural language

For example: "Where is an incoming SMS report parsed?"

Retrieve relevant code

The system searches the indexed Ushahidi repository to find relevant source chunks.

Understand the answer

The AI generates an explanation grounded in the retrieved context, with source references.

The Retrieval-Augmented Generation (RAG) pipeline workflow

STEP 1

Code ingestion

Collect PHP source files and markdown documentation from the Ushahidi repository.

STEP 2

Chunking and extraction

Extract code structure and split source files into searchable chunks.

STEP 3

Embedding generation

Sentence Transformers convert code chunks into vector representations.

STEP 4

Vector storage

Store embeddings and metadata in ChromaDB.

STEP 5

Retrieval and ranking

Retrieve relevant code chunks and rank them according to the question.

STEP 6

Answer generation

The LLM generates a grounded explanation using the selected context.

STEP 7

Visual response

Display the answer, source references and supported visualizations in the UI.
