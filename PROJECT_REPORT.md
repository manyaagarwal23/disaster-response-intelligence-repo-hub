# Disaster Response Intelligence Repo Hub
**Complete Project & Architecture Onboarding Report**

Welcome to the team! This document is designed to take you from zero to 100 on how our project works, what technologies we use, and exactly how the code is structured from end to end.

---

## 1. What is this project?
The **Disaster Response Intelligence Repo Hub** is an AI-powered developer onboarding tool. 
We are analyzing **Ushahidi**, a massive, open-source PHP crisis-mapping platform. Ushahidi is highly complex, making it difficult for new developers to understand how its classes, methods, and APIs interact.

Instead of forcing developers to read thousands of lines of PHP, we built an AI chatbot. Developers can ask questions in plain English (e.g., *"How does the LanguagesController work?"*), and our AI will read the actual source code and provide an accurate, easy-to-understand answer with visual flowcharts and direct source code references.

We achieve this using **Retrieval-Augmented Generation (RAG)**.

## 2. The Technology Stack
Here is every technology we use and *why* we use it:

### Backend & AI
*   **Python 3.10:** The core programming language powering our logic.
*   **FastAPI:** A high-performance web framework used to run our server (`app.py`) and expose our `/api/ask` endpoint to the browser.
*   **ChromaDB:** A local "Vector Database". Instead of saving data in tables (like SQL), it saves data as mathematical vectors. This allows us to search for code by *meaning* rather than exact keywords.
*   **SentenceTransformers (BGE-base):** The AI model that converts text/code into those mathematical vectors for ChromaDB.
*   **LangChain:** A powerful framework used to orchestrate our AI prompts and connect our data to the Groq LLM.
*   **Groq (Qwen Model):** Our cloud-based Large Language Model (LLM) provider. We use it for its blazing fast inference speeds to generate human-readable answers.

### Frontend (UI)
*   **HTML5 / Vanilla JavaScript:** Handles the webpage structure and API requests without needing heavy frameworks like React.
*   **Vanilla CSS (Glassmorphism Theme):** A modern, premium design system featuring frosted glass panels, vibrant colored cards, and deep dark-mode backgrounds.
*   **Mermaid.js:** A JavaScript library that takes markdown text generated by our AI and automatically turns it into beautiful visual flowcharts.

### DevOps & Testing
*   **Pytest:** Our automated testing framework.
*   **GitHub Actions:** A CI/CD robot that automatically runs our tests every time we push code.
*   **Sweep.dev:** An AI assistant installed on GitHub that can automatically read issues and write Pull Requests.

## 3. End-to-End Workflow (How it Works)

The project operates in two distinct phases:

### Phase A: Building the Brain (Ingestion)
Before the user can ask anything, we must "read" the codebase.
1.  **Extraction:** `php_extractor.py` scans the `ushahidi/` PHP files. It intelligently identifies classes, methods, and dependencies.
2.  **Embedding:** `ingest.py` takes these extracted code chunks, uses `SentenceTransformers` to convert them into numbers, and saves them into the `chroma_db/` folder.

### Phase B: Answering Questions (Generation)
1.  **User Asks:** The user types a question in the UI and hits send. JavaScript sends this to FastAPI (`app.py`).
2.  **Search:** FastAPI sends the question to `rag_api.py`. The question is converted into a vector, and ChromaDB is searched for the closest matching PHP code files.
3.  **Re-Ranking:** Because search isn't perfect, `rag_api.py` hands the top 10 results to `llm.py`. LangChain and Groq quickly read the 10 files and discard the irrelevant ones, keeping only the best 3.
4.  **Generation:** The best 3 files and the user's question are sent to `generator.py`. LangChain and Groq write a final JSON response containing a Simple Summary, Technical Details, and Mermaid flowchart code.
5.  **Display:** The JSON is sent back to the browser, where JavaScript renders it into colorful, stackable Glassmorphism cards and draws the diagram.

## 4. File and Folder Breakdown

If you are looking for where to edit code, here is your map:

### 📁 Root Directory
*   `ushahidi/`: The actual disaster-response codebase we are analyzing.
*   `sweep.yaml`: Configuration telling the Sweep AI bot how to behave.
*   `.github/workflows/ci.yml`: The GitHub Actions instruction file for automated testing.
*   `PROJECT_REPORT.md`: This file!

### 📁 The Core Engine (`rag/`)
*   **`app.py`**: The main Web Server. Start the project by running `python app.py` here. It serves the HTML and handles API requests.
*   **`rag_api.py`**: The Search Engine. Connects to ChromaDB and retrieves code chunks based on the user's question.
*   **`llm.py`**: The Filter. Uses LangChain to re-rank and filter search results for maximum accuracy.
*   **`generator.py`**: The Writer. Uses LangChain to formulate the final answer and structure the JSON response for the frontend.
*   **`chroma_db/`**: The folder containing our saved vector database.

### 📁 Ingestion Scripts (Run these to update the DB)
*   **`php_extractor.py`**: The parser that reads PHP files and understands their structure.
*   **`ingest.py`**: The script that runs the extractor and saves the results into ChromaDB.

### 📁 Frontend (`rag/frontend/`)
*   **`templates/index.html`**: The structure of the web UI, including the sidebar, Chat tab, and About tab.
*   **`static/css/style.css`**: All the visual styling, animations, colors, and Glassmorphism effects.
*   **`static/js/script.js`**: The frontend logic that talks to `app.py` and renders AI messages.

### 📁 Testing (`rag/tests/`)
*   Contains automated Pytest files (e.g., `test_extractor.py`) to ensure our PHP parsing logic never breaks.
